## Applied behavior

The production button is functional again, not diagnostic-only: current owned video -> existing explicit ID path if available -> selected official Share -> fresh official Copy link -> unchanged native clipboard/Seal quick activity. Playback CDN URLs remain prohibited for video handoff.

Legacy exact labels remain. Descriptive accessible names are accepted only on the observed role/button/action/component footprint, within the passed video's unique single-video owner and existing bounds, with exactly one eligible action. A broad label is not accepted from unproven global portals, other videos, shared multi-video owners, arbitrary post text or unlabelled icons. Explicit Share command prefixes are supported; Send/إرسال must mention a video/reel/post, never a generic message-to-author command. Canonical action mapping cannot escape the owner being examined.

Mobile Copy-link actions may use action/component attributes and descriptive aria names; nested recognized wrappers are deduplicated into one action. Pre-existing sheets, ambiguous fresh copy actions, changing source/page, ordinary user gestures and timeouts keep their prior cancellation behavior. No clipboard history is read. Only the fresh official copied value may route to native, whose post-only validation remains unchanged.

On a reportable Share/Copy failure, the existing local V2 dialog includes numeric attempt stage/reason/action flags. Native formatter independently strips unknown strings and clamps these fields. It does not automatically upload/copy anything. A returned click is not proof a share sheet opened. Exact code meanings are in the integration README. The fallback toast remains if report capture is unavailable.

No modifications to Like/fullscreen/gesture guards, no idle poller/observer/network hook/token extraction, no internal downloader/chooser. Separate story-image transfers remain unchanged.
