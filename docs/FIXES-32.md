# البناء32 — تثبيت الشريط بقياس WebView وتصغير الكرة

بلاغ المستخدم في31 يؤكد أن موضع الشريط في حسابه لم يُصلح. لا نعامل اختبارات الصفحات المحلية كدليل على حسابه.

- Android ينشر أبعاد WebView الفعلية (عرض/ارتفاع المحتوى، لا الشاشة ولا أشرطة النظام) قبل الحقن وعند تغير الحجم. التحويل إلى CSS يتم بنسبة عرض الصفحة إلى العرض الفعلي، مع مراعاة التكبير ولوحة المفاتيح.
- حساب نهاية الريلز لا يعتمد على innerHeight وحده إذا توفر القياس الأصلي. الشريط نفسه أصبح مثبتًا بإحداثيات viewport صريحة وinline!important بدل الاعتماد على bottom في حاوية أدوات الفيديو فقط.
- اكتشاف شريط وقت مؤكد قرب التذييل ما زال هو المرجع للمحاذاة، مع استعادة الأصل عند تعطيل الميزة وحماية الصوت/البحث/الحساب. لا يوجد حجب عام لعناصر DIV رمادية.
- الكرة الأصلية ⚽️ بقيت كما هي؛ صُغّر الخط من18px إلى16px، مع إبقاء مساحة الصندوق لمنع القصّ ودورة3s.
- التحديد23 وخدمة الصوت وإصلاح شفافية قائمة التفاعلات لم تتغير.

## التحقق

اختبارات DOM وChromium تتعمد جعل innerHeight أقل من نافذة المحتوى بـ56px مع بقاء CSS layout بحجمه الحقيقي، وتبقي شريطًا أصليًا أسفل الوصف على body محوّل. تتحقق من استخدام قياس WebView، ومحاذاة الشريط، وبقائه أسفل النص، واستعادة الأصل، وحجم الكرة16px.

هذا يفحص فرضية اختلاف قياس الارتفاع ولا يثبت أنها سبب بلاغ الحساب تحديدًا؛ لا DOM مسجّل من جهاز المستخدم.
