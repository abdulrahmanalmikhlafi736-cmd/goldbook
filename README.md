# FPRO — أندرويد / Kotlin / Jetpack Compose

عميل ويب مستقل باللغة العربية لفيسبوك، الإصدار **0.0.1**، الحزمة **com.almekhlafi.FPRO**، المطور **عبدالرحمن المخلافي**. Android 6.0 (API 23) فأحدث. ترخيص الشيفرة الجديدة GPL-3.0، انظر [LICENSE](LICENSE). ليس منتجاً رسمياً لفيسبوك ولا تابعاً لشركة Meta.

## البناء وإنتاج APK

1. ثبّت Android Studio مع **JDK 17** وAndroid SDK Platform **35**، واقبل تراخيص SDK.
2. افتح هذا المجلد كمشروع Gradle. اجعل Android Studio ينشئ `local.properties` الذي يشير إلى SDK، أو عيّن `ANDROID_HOME`.
3. من جذر المشروع:

```sh
./gradlew testDebugUnitTest lintDebug assembleDebug
# Windows: gradlew.bat testDebugUnitTest lintDebug assembleDebug
```

الناتج القابل للتثبيت والموقّع بمفتاح التطوير: `app/build/outputs/apk/debug/app-debug.apk`.

```sh
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

بناء المتجر: استخدم **Generate Signed Bundle / APK** في Android Studio مع مفتاحك الخاص. لا تستخدم مفتاح التطوير للنشر ولا ترفع مفاتيحك إلى Git. `assembleRelease` وحده ينتج إصداراً غير موقع؛ لا يحتوي المشروع على مفاتيح إنتاج.

يوجد Workflow في `.github/workflows/android.yml`: عند دفع التغييرات إلى GitHub أو تشغيله يختبر ويبني ويرفع APK إلى **Artifacts → FPRO-0.0.1-debug**. هذا ملف بناء مُعدّ للتنفيذ وليس ادعاءً بأنه نُفّذ بالفعل.

**التحقق الأحدث (versionCode 7):** نجح [بناء وفحص المصدر 39900961741](https://github.com/abdulrahmanalmikhlafi736-cmd/goldbook/actions/runs/39900961741) و[اختبار الأجهزة 39900957233](https://github.com/abdulrahmanalmikhlafi736-cmd/goldbook/actions/runs/39900957233). يتوفر [APK المصغر المتحقق منه — ملف ZIP نحو 1 MB](https://github.com/abdulrahmanalmikhlafi736-cmd/goldbook/actions/runs/39900957233/artifacts/12478074798). إثبات العرض يشمل صور الشاشة الفعلية وصفحة الدخول الحية ولمس حقلها؛ لا يشمل حساب المستخدم أو ضمان جميع وظائف الموقع.

**سجل التحقق السابق:** لا تتوفر Java أو Android SDK محلياً في بيئة التحرير، لكن نجح [بناء GitHub Actions رقم 39884268393](https://github.com/abdulrahmanalmikhlafi736-cmd/goldbook/actions/runs/39884268393) في تنفيذ `testDebugUnitTest lintDebug assembleDebug` واختبارات JavaScript، ورفع APK باسم `FPRO-0.0.1-debug` وتقارير الفحص. أُصلح إعداد SDK بتحديد الحزم المطلوبة دون حزمة `tools` القديمة. لم يُختبر التطبيق على جهاز فعلي بعد؛ نجاح البناء ليس ضماناً لسلوك فيسبوك الحي أو اكتمال الوظائف.

## ما ينفذه المشروع

- واجهة أصلية بـCompose وMaterial 3 واتجاه RTL، إعدادات محفوظة، شاشة افتتاحية ذهبية بخمس نقاط متحركة مخصصة (ليست أصلاً رسمياً من Meta).
- WebView واحد يحفظ الجلسة والكوكيز، رفع الملفات عبر منتقي النظام، معالجة أخطاء الشبكة دون تجاوز أخطاء TLS.
- الموقع يملأ مساحة التطبيق مع زر ⚙ عائم فقط؛ أزيل شريط FPRO وزرا فيسبوك والرسائل. قوائم الموقع الأصلية هي وسيلة التنقل. الزر العائم ليس جزءاً من DOM الخاص بشعار Meta.
- خيارات مستقلة للإعلانات والمقترحات والريلز والقصص والأشخاص والمجموعات، عبر مرشحات DOM محدودة ومراقب تغييرات مؤجل.
- 12 اختياراً لونياً حسب الأسماء المذكورة في الطلب (القائمة المطلوبة احتوت 12 اسماً لا 11)، الوضع الداكن وAMOLED، Material You على API 31+ لواجهة Compose. تلقائي لا يغير ألوان الموقع. ألوان الموقع عبر CSS اجتهادية وليست إعادة تلوين كاملة مضمونة لكل نسخة.
- مطابقة لون الشريط مع `theme-color` أو خلفية الصفحة عند اكتمال التحميل، وليس مراقبة مستمرة لكل تغير لوني.
- زر تنزيل شفاف على عناصر HTML video، تحريك بالضغط 400ms ثم السحب، حفظ الموضع النسبي لحاوية الفيديو في تخزين أصل الموقع، مشاركة الرابط إلى الحزمة المحددة.
- تنزيل داخلي للروابط المباشرة HTTPS عبر DownloadManager، كوكيز المصدر، قائمة أصلية داخل التطبيق بتقدم/حالة/إلغاء/حذف وفتح الفيديو. يُعرض تأكيد أصلي قبل كل تنزيل. حفظ داخل مجلد Movies الخاص بالتطبيق؛ تُحذف الملفات عند إزالة التطبيق. الفتح قد يشغّل مشغل فيديو خارجي.
- تقدم فيديو بألوان قوس قزح وكرة، تحديد النص حيث تسمح الصفحة، تكبير اختياري، تثبيت banner حيث توفره الصفحة، وضع سطح مكتب، عكس الاتجاه.
- رسائل الويب ضمن نفس WebView مع زر فيسبوك، ملء شاشة الفيديو بالنقر المزدوج، وضع مغمور، رجوع يغلق واجهة الإعدادات/التنزيل/الفيديو/حوار الصفحة المعروف ثم يصعد لأعلى ثم يعود في السجل ثم يغلق التطبيق.
- PiP على Android 8+ عند وجود فيديو يعمل، وفق دعم الجهاز وWebView. أقدم من ذلك لا يدعم النظام PiP. يمكن إبقاء مشاهدة الفيديو عند المغادرة؛ لا توجد خدمة صوت دائم مستقلة.
- روابط خارجية إلى التطبيقات/المتصفح، بطاقة المطور ورابط واتساب `+967781764759`.

## قيود لا يمكن حلها بوعد برمجي

1. **WebView ليس تطبيق Meta الرسمي.** تسجيل الدخول والرسائل والريلز والقصص والتعليقات تعتمد على ما يقدمه الموقع لحسابك وWebView لديك. يمكن لفيسبوك منع الدخول أو طلب فتح تطبيقه أو تغيير بنيته؛ لا يمكن تجاوز سياساته أو المصادقة. لا يوجد ضمان أداء «صفر تهنيج» أو سرعة أعلى دائماً من المتصفح.
2. **الحزمة ليست API.** ACTION_SEND يشارك رابطاً فقط ويخرج إلى التطبيق المستهدف. لا يستطيع أندرويد إدراج Activity تطبيق آخر داخل FPRO أو قراءة قائمة تنزيلاته وتقدمه دون تكامل موثّق منه. القائمة هنا تخص تنزيلات FPRO فقط، وليست قائمة التطبيق الخارجي. لا يتم ادعاء العكس أو إنشاء تقدم وهمي.
3. **ليس كل فيديو قابلاً للتنزيل.** روابط `blob:`/MediaSource والبث المجزأ/DRM والقصص المصورة ليست ملفات MP4 مباشرة. لا يوجد استخراج محمي أو تجاوز حماية، وقد تنتهي صلاحية روابط CDN. لا يوجد ضمان تنزيل أي فيديو/ريلز/ستوري. زر المشاركة يحاول التقاط رابط المنشور من حاويته، وإلا يشارك رابط الصفحة الحالي.
4. **الإعلانات بكل اللغات ليست قابلة للتحديد المضمون.** توجد مطابقة لعناوين عربية مع إزالة التشكيل والتطويل، وإنجليزية وألمانية وفرنسية وإسبانية وإيطالية لبعض العناوين. لا يوجد ادعاء بتغطية كل اللغات/التقسيمات المتعمدة للنص. الحجب لا يعترض الشبكة ولا يعطل إعلانات الفيديو المحمية.
5. **لا يوجد نظام push أصلي لإشعارات Meta ولا صوت خلفي دائم.** تبقى إشعارات الموقع داخل الصفحة وفق ما يتيحه؛ ليست إشعارات حساب تصل بعد إغلاق التطبيق. مكالمات الميكروفون/الكاميرا غير مدعومة؛ أذونات WebRTC مرفوضة عمداً. يمكن رفع صور وملفات موجودة عبر منتقي النظام.
6. تكبير بعض صفحات الهاتف، تحديد النص، تثبيت شريط Meta، CSS الداكن وملء الشاشة قد تتأثر ببنية الصفحة وسياساتها. لا يوجد شريط تنقل أصلي إضافي؛ خيار sticky يحاول تثبيت شريط الموقع نفسه.

إذا كان اشتراط «كل الميزات بلا استثناء» حرفياً، فهذا المشروع **لا يحقق ذلك الاشتراط**: يحتاج بعضه API من التطبيق الخارجي وMeta وبعضه تمنعه قيود النظام/الموقع. لا توجد شيفرة وهمية تُخفي هذه الحدود.

## البنية والأمان

- `MainActivity.kt`: دورة حياة WebView، Compose، التنقل، منتقي الملفات، الفيديو وPiP.
- `SettingsPanel.kt` / `Preferences.kt`: الإعدادات والتخزين المحلي.
- `DownloadStore.kt`: التنزيلات الحقيقية والاستعلام عن حالة النظام.
- `assets/facebook.js`: CSS وDOM وفيديو؛ حقن متكرر آمن دون تكرار المراقبين.
- لا `addJavascriptInterface` مكشوف، ولا وصول إلى ملفات الجهاز من الويب، ولا HTTP cleartext، ولا خادم يجمع بيانات تسجيل الدخول. تبقى الجلسة في تخزين WebView المحمي بعزل أندرويد. النسخ الاحتياطي معطل. لا تُعطل TLS أو Safe Browsing.
- فحص المضيف يعتمد على حدود النطاق، لا احتواء النص. المخططات الخارجية محدودة بـhttp/https/mailto/tel. المشاركة والتنزيل إجراءات يوافق عليها المستخدم.
- الأرشيفات وملفات DEX الموجودة مسبقاً في المستودع لم تُستخدم ولم تُعدّل؛ المشروع الجديد ليس إعادة تجميع لشيفرتها مجهولة المصدر أو ترخيصاً لها.

## تجربة الهاتف — versionCode 7

- نقطة الدخول `https://m.facebook.com/` مع وكيل مستخدم WebView المحمول الأصلي؛ يقرر الموقع نسخة الهاتف. لا يُستخدم خادم وسيط أو صفحة تسجيل دخول بديلة.
- الإطارات المضمنة HTTPS لم تعد تُعامل كروابط خارجية محظورة؛ الروابط الرئيسية الخارجية ما زالت تفتح خارج التطبيق.
- يظهر خطأ الاتصال ورمزه أو فشل TLS دون تجاوز الشهادات. بعد 25 ثانية يتم فحص وجود نص/صور/فيديو في DOM؛ هذا تشخيص للصفحة الفارغة **وليس إثبات عرض صحيح أو نجاح تسجيل الدخول**. يتطلب التشخيص Android System WebView محدثاً؛ الصفحات القائمة على canvas/DOM مغلق قد تعطي نتائج مختلفة.
- لبناء نسخة أصغر قابلة للتثبيت: `./gradlew assembleCompact`. تستخدم R8 وتقليص الموارد ولا تحتوي أدوات معاينة Compose. المسار `app/build/outputs/apk/compact/app-compact.apk`، واسم artifact هو `FPRO-0.0.1-compact`.
- compact تستخدم مفتاح debug لأغراض تجربة الأجهزة، وليست إصدار متجر. استمرارية التحديث فوق APK من تشغيل CI سابق ليست مضمونة لأن مفتاح debug في runner مؤقت قد يختلف؛ إذا رفض أندرويد التحديث بسبب التوقيع، إزالة النسخة السابقة تحذف الجلسة والتنزيلات الخاصة بها، لذلك لا تُزلها دون حفظ ما يلزم.
- لم تُؤكد بعد استجابة فيسبوك الحية على هاتف المستخدم؛ عدم ظهور محتوى يستلزم قراءة رسالة التشخيص الجديدة وتحديد إصدار النظام وWebView والشبكة، وليس الادعاء بأن نجاح Gradle يحل ذلك تلقائياً.

## تشخيص الشاشة الرمادية

- هوية WebView الأصلية هي الافتراضية. يوجد خيار توافق متصفح اختياري؛ لا يُفرض انتحال هوية Chrome على الموقع.
- تعديلات DOM والمرشحات وألوان الموقع وأدوات الفيديو معطلة افتراضياً، وتتطلب تفعيل «أدوات وتعديلات الصفحة». تعطيلها بعد استخدامها يعيد تحميل الصفحة الأصلية.
- أثبتت لقطات التشغيل 39899234428 أن الحاوية الأصلية ترسم نموذج الدخول بينما الحاوية السابقة بقيت بيضاء رغم وجود نصوص وحقول في DOM. الإصدار 7 يفصل WebView في FrameLayout أصلي، ويستخدم Compose كطبقة تحكم شفافة، ويؤخر بدء التحميل حتى تركيب الحاوية وزوال شاشة البدء. نجح اختبار APK المصغر على Android 15 و16 في التشغيل [39900288305](https://github.com/abdulrahmanalmikhlafi736-cmd/goldbook/actions/runs/39900288305)، بما فيه رسم الصفحة المحلية وظهور عناصر فيسبوك الحقيقية. صُحّح سباق توقيت الاختبار المحلي مع شاشة البدء، ثم نجحت جميع وظائف مصفوفة الأجهزة في التشغيل [39900957233](https://github.com/abdulrahmanalmikhlafi736-cmd/goldbook/actions/runs/39900957233)، بما فيها لمس حقل الدخول والتركيز عليه دون إدخال بيانات حساب. لا تزال تجربة الهاتف والحساب المسجل غير مؤكدة.
- المهلة الأصلية كانت تتوقف على استجابة JavaScript؛ أصبح فحص التعطل الأصلي يعمل حتى إذا لم يصل رد JavaScript أو لم يُرسل `onPageStarted`. يحاول تأكيد وجود نص بعد 24 ثانية ثم يعرض تشخيصاً بعد ثانية إضافية عند عدم التأكيد. تأكيد النص في DOM **ليس ضماناً لرسم بكسلات على كل جهاز**.
- تتضمن الإعدادات إصدار مزود WebView وحالة التحميل والعنوان وأبعاد WebView، وزر نسخها. راجع معلومات العنوان قبل مشاركتها، فقد يحتوي رابط الموقع على بيانات شخصية؛ لا يسحب التطبيق كلمات المرور أو الكوكيز إلى التشخيص.
- يوجد اختبار محلي أخضر عبر الإعدادات، مستقل عن الإنترنت، مكتوب بصياغة JavaScript قديمة متوافقة. **ليس صفحة فيسبوك مزيفة**؛ وظيفته فصل أعطال الرسم عن أعطال اتصال الموقع. يوجد خيار للرسم البرمجي للأجهزة التي تعرض سطح WebView رمادياً؛ قد يخفض أداء الفيديو، لذا لا يُفرض على الجميع.
- المزود القديم الذي يعلن إصدار Chromium أقل من 80 يُعرّف بوضوح بدلاً من اعتباره متصفحاً حديثاً. حدّث Android System WebView/Chrome من المتجر عند ظهور التحذير. حتى إصدار أحدث من 80 لا يضمن توافق كل وظائف الموقع الحية.

### اختبارات عرض حقيقية، لا نجاح تجميع فقط

يضيف `.github/workflows/device.yml` اختباراً على محاكيات Android 10 وAndroid 15 وAndroid 16:

- `app/src/androidTest`: عرض صفحة HTML محلية داخل WebView وفحص بكسلات الشاشة وتنفيذ JavaScript، دون الاعتماد على فيسبوك.
- `device-tests`: وحدة `com.android.test` مستقلة، ذاتية instrumentation، تستخدم UI Automator مع APK المصغر الحقيقي في عملية منفصلة. لا تستورد شيفرة التطبيق ولا تُعطّل تصغيره أو تشويشه؛ تفتح زر الإعدادات الحقيقي والاختبار المحلي، وتفحص بكسلاته، ثم تتحقق من ظهور نص فيسبوك الحقيقي عبر HTTPS وشجرة الوصول. لا توجد استجابة شبكة وهمية أو حساب مسجّل الدخول.
- تحفظ لقطات الشاشة والتقارير في Artifacts. عند نجاح الاختبار المصغر فقط، ينشر نفس APK الذي جرى اختباره باسم **`FPRO-compact-device-verified-API35`** أو **`FPRO-compact-device-verified-API36`** بحسب بيئة التحقق. لا تعتبر مجرد وجود artifact تشخيصي دليلاً على نجاح الاختبارات؛ راجع نتيجة التشغيل.

```sh
./gradlew :app:connectedDebugAndroidTest
./gradlew :device-tests:connectedCompactAndroidTest
```

تحتاج هذه الأوامر جهازاً/محاكياً مناسباً وSDK. فحص فيسبوك الحي يتطلب اتصالاً وقد يتأثر بتغييرات الموقع. الاختبارات لا تتحقق من تسجيل الدخول بحساب أو الرسائل/الفيديوهات المحمية، ولا تثبت سبب الشاشة الرمادية على هاتف لم نقرأ تشخيصه بعد. الفشل الأول لاختبار المحاكي استخدم صياغة JavaScript غير مدعومة في مزوده القديم؛ صُحّح الاختبار، ولا يُنسب ذلك الفشل وحده إلى فيسبوك أو الهاتف.


## تحسين أدوات الصفحة — versionCode 8

- تشغيل أداة أو اختيار لون يفعل مفتاح تعديلات الصفحة تلقائياً. إيقاف المفتاح العام يعيد الصفحة الأصلية ويحفظ الاختيارات؛ الاختيارات القديمة تُرحّل فقط إذا لم يختر المستخدم إيقاف المفتاح صراحةً.
- خيار «إخفاء شريط فتح التطبيق أو تثبيته» مستقل، ويبحث عن روابط التثبيت وتسميات الفتح مع حماية نموذج الدخول من الإخفاء.
- المرشحات تتعرف على تسميات عربية/إنجليزية وعناصر منشورات الهاتف والقصص، بما فيها النصوص الموزعة على عناصر متعددة والتحديثات أثناء التمرير. تبقى اجتهادية؛ لم يُختبر حساب مسجل الدخول أو جميع نسخ واجهة Meta.
- ألوان الموقع تشمل متغيرات CSS والأزرار/الروابط الزرقاء الفعلية، وتستعيد الأصل عند اختيار «تلقائي». لا تُعاد تلوين الصور. تُراعى قراءة النص فوق الألوان الفاتحة.
- أدوات الفيديو تتبع موضع الفيديو أثناء التمرير وتغيّر حجمه. شريط قوس قزح يعكس الزمن الحقيقي ويمكن سحبه للتقديم والتأخير عندما تكون المدة متاحة؛ البث الحي غير القابل للسعي لا يُعرض كأنه قابل للسعي. قد يستخدم ملء الشاشة مشغل النظام دون أدوات HTML الإضافية.
- التنزيل يستخدم رابط HTTPS متاحاً من الفيديو أو بيانات الوسائط التي وفّرها الموقع بالفعل. لا يفك DRM ولا يجمع مقاطع DASH/HLS ولا يعد بتحويل كل blob إلى ملف. الحجم المجهول يظهر بمؤشر غير محدد، والتنزيل الناجح يعرض 100% بدلاً من البقاء على 0%.
- اختبارات DOM عبر jsdom هي تبعية تطوير فقط، وليست ضمن APK. تشمل استعادة العناصر، الإعلانات والقصص وشريط التثبيت والألوان والوسائط المتغيرة والسعي في شريط التقدم. وتوجد اختبارات APK مستقلة لاختيار الذهبي عبر الإعدادات وفحص بكسلات زر الدخول الحقيقي واختفاء شريط التثبيت مع بقاء نموذج الدخول.
